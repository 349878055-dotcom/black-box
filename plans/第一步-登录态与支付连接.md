# 工作台 4.0 · 做 Skill 第一步：登录态 + 支付连接（必跑流程）

> **本流程是每个 skill 开工前的第一步，必须先跑通这两件事，才能往下做。**
> 核心：**①登录态能拿到 ②支付连接能拿到**，两件事必须同时满足；不满足就退而求其次（确认页客户自己点）。

---

## 一、为什么第一步就是这两件事

一个 skill 的本质 = **登录态** + **最后的支付连接**。这两件事由"帽子"（环境身份：H5 / 微信 / App / token）决定。

- 帽子不同 → 登录方式不同
- 帽子不同 → **支付连接可能拿不到**（有的帽子根本出不来支付链接）

**先确认"帽子"能同时拿到登录态 + 支付连接，再谈自动化；否则全是白做。**

---

## 二、第一步要确认的两件事

### ① 登录态能拿到吗？

H5 帽子下登录有 2 种方式：

| 方式 | 原理 | 取舍 |
|---|---|---|
| **API 登录** | 云端直连调登录接口（如 `passport.meituan.com/mobilelogin`） | 快、可自动化；但可能被滑块/图形验证、设备指纹拦 |
| **H5 网页登录** | 内置浏览器打开登录页，真人输手机号+验证码 | 稳、能过滑块；但要真人配合一次，登录态存 cookie 复用 |

其他帽子：微信帽子 = 微信授权；App 帽子 = App token/uuid（真机登录+抓通信）；接口 token = Bearer。

**判断**：这个 skill 用哪种方式能稳定拿到登录态？（API 优先，网页兜底）

### ② 支付连接能拿到吗？

| 支付通道 | 虾米能否拉起 | 例子 |
|---|---|---|
| **alipays://（支付宝 scheme）** | ✅ 普通环境可拉（拉起支付宝 App） | 途牛 |
| **微信 JSAPI（wx.requestPayment）** | ❌ 必须真微信 SDK，帽子/UA 替代不了 | 美团 |
| **H5 收银台（https）** | ✅ 手机浏览器打开 | 视平台 |
| **接口内处理** | 不走外部支付 | glyy |

**判断**：这个 skill 的帽子下，能不能拿到支付连接？虾米能不能拉起？

---

## 三、两条路径（决定往下怎么做）

### 路径 A：✅ 登录态 + 支付连接都能拿到
→ 正常做自动化 skill：登录态复用 + API 下单 + 拿支付连接 + 虾米拉起支付，客户最后点确认。

### 路径 B：⚠️ 拿不到支付连接（如美团 H5）
→ **退而求其次**：
```
登录态能拿到（看店/搜索/点菜/加购/结算）
→ 生成"确认页面/订单链接"
→ 返回客户 → 客户用微信/Safari 打开 → 客户自己点确认 → 再出支付
```
- 虾米做到"下单前"（登录态 + 加购 + 结算 + 生成链接）
- **最后一步（确认订单 + 支付）由客户自己在微信/浏览器里点**
- 客户唯一动作 = 打开链接 + 点确认

---

## 四、第一步执行清单（新 skill 开工先填）

```
□ ① 帽子：用哪个环境身份进去？（H5 / 微信 / App / token）
□ ② 登录态：这个帽子下怎么登录？（API登录 / 网页登录 / 授权）
   → 实测能拿到登录态吗？存哪？能复用/续期吗？
□ ③ 支付连接：这个帽子下能拿到支付连接吗？
   → 能：什么格式（alipays 可拉 / JSAPI 要真微信 / H5 收银台）？虾米能拉起吗？
   → 不能：换帽子（如微信帽子）能拿到吗？还是只能走"确认页客户自己点"？
□ ④ 定路径：路径 A（全自动到拉支付）还是 路径 B（退而求其次，确认页客户点）？
```

---

## 五、结论

**每个 skill 第一步先跑这两件事：登录态能不能拿到 + 支付连接能不能拿到。**
- 都能 → 路径 A（自动化）
- 支付拿不到 → 路径 B（确认页客户自己点，虾米做到下单前）
