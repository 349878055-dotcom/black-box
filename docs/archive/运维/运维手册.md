```

│  3) 云端 bridge.register(device_id) → 标记「设备在线」            │

              │ http / ws :80
              ▼
┌─ 腾讯云 140.143.144.28 ───────────────────────────────────────┐
│  nginx :80 → proxy_pass http://127.0.0.1:19000                │
│    （已配 Upgrade/Connection，WS 正常代理）                      │
│  shimeban-cloud.service（python -m cloud.cloud_orchestrator.main）│
│    FastAPI :19000，路由 /api/v1/ws → SessionExecutor → bridge    │
└──────────────────────────────────────────────────────────────┘
```

**关键文件**：
- 手机端：`app/src/ui/assets/ui.html`（`doLogin`/`getBase`/`connectWS`/`wsUrl`）

- 云端设备表：`cloud/cloud_orchestrator/channel/bridge.py`（`_devices` 在线判定）
- 云端注册拦截：`cloud/cloud_orchestrator/adapters/registry.py`（`run` 里 `bridge.has(device_id)` 检查）

## 三、「连不上」全部根因与解法

### 根因 ① 虾米 App 未登录 / 登录态丢失（最常见）
- **现象**：凭据库空 → `connectWS()` 直接 return → 云端永远「手机未在线」。
- **触发**：清 App 数据 / 重装 / token+refresh 双双失效。
- **解法**：手机打开虾米 App → 点顶部「未登录」→ 输入邮箱+密码登录。登录成功即自动连 WS。
  - ⚠️ 云端无法代填手机 WebView 登录框。**登录必须真人在手机上输一次**。

### 根因 ② xiami_base 缓存了旧地址
- **现象**：App 读 `localStorage['xiami_base']`，若曾存过旧 IP 就连错地方。
- **解法**：清虾米 App 数据/重装 → base 回默认 → 重新登录。

### 根因 ③ 断线后无法自动重连
- **现象**：token 失效后重连永远失败；App 进程被系统杀 WS 直接没了。
- **解法**：
  - 后台进程限制：`adb shell settings put global background_process_limit -1`
  - 保持虾米在后台存活，别「一键清理」杀它。

### 根因 ④ 云端服务/nginx 异常（已排除）
- **现状**（2026-08-11 实测）：health OK、systemd running、WS 代理正常。
- **若真要查**：`systemctl status shimeban-cloud`、`curl -s http://127.0.0.1:19000/health`。

## 六、启动铁律：只用 systemd，禁止 nohup

> 踩了 4768 次崩溃循环换来的教训。

**一句话铁律：云端服务（19000 端口）只能 `systemctl restart shimeban-cloud.service` 管理，禁止任何 nohup 手动启动。**

### 踩坑根因

两套启动方式（systemd vs nohup）**抢同一个 19000 端口**。nohup 先占住 → systemd 每次启动 `Errno 98: address already in use` → 无限崩溃循环（累计 NRestarts=4768），但 nohup 进程 health 一直 ok → **表面正常，实际 systemd 全在失败**。

### 30 秒必查

```bash
# 1) 19000 端口是谁占的（必须只有一个 systemd 进程）
ss -tlnp | grep 19000

# 2) systemd 是否在崩溃循环
systemctl show shimeban-cloud.service -p NRestarts -p ActiveState

# 3) 有没有 nohup 残留进程
pgrep -af 'cloud_orchestrator.main'
```

### 踩了怎么恢复

```bash
# ① 杀掉 nohup 手动进程（释放 19000）
kill <nohup_pid>

# ② 确认端口释放
ss -tlnp | grep 19000   # 应无输出

# ③ 让 systemd 接管
echo Jtao_8505 | sudo -S systemctl restart shimeban-cloud.service
sleep 8
curl -s http://127.0.0.1:19000/health   # {"status":"ok"}
```

### 防再犯清单

1. **重启服务永远只用**：`echo Jtao_8505 | sudo -S systemctl restart shimeban-cloud.service`
2. **绝对禁止**：`nohup bash run.sh &`、`nohup python -m cloud.cloud_orchestrator.main &`
3. **部署代码**：用 `python3 tools/deploy_cloud.py`（内部已内置 systemctl restart）
4. **run.sh 只作历史参考，不要执行**
5. **看到 `address already in use`**：先想"是不是又有 nohup 进程"，按上面恢复

## 七、易错点总结

1. 登录是唯一手动步骤，云端无法代填。
2. 别杀虾米后台，Android 后台进程限制要 `-1`。
3. 登录态会失效，refresh 401 后必须重登。
4. 手机 ping 丢包是腾讯云 ICMP 限流假象，TCP/WS 正常。
5. 设备键 = 邮箱：`device_id=349878055@qq.com`。
6. 19000 端口只能有 systemd 一个管家。
