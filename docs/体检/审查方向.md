# 个人助理5 · 代码审查方向（路线图）

> 本系统的本质：把各平台的**网页逆向 API 封装成 skill**（`contract.json` + `api.py` + 登录态），
> 由云端 **AI 主代理**按 contract 声明「点菜」并调用真实接口，帮客户把事办成。
> 边界铁律：**不代付、无高风险**；交付只有 `query` / `action` / `pay_url` / `scheme` 四类（见 [`体检方案.md`](体检方案.md)）。

## 6 个审查方向（按顺序推进）

| # | 方向 | 一句话定位 | 审查角度（进入该方向时展开） |
|---|------|-----------|------------------------------|
| 1 | 契约一致性 | AI 看到的菜单（`contract.json`）与实际实现（`api.py`）是否对得上 | 声明↔实现、参数↔来源、交付类型 |
| 2 | API 逆向健壮性 | 真实请求是否可靠（请求构造/签名/超时/异常/响应解析） | 请求构造、异常兜底、响应解析 |
| 3 | 登录态生命周期 | 登录态从哪来、存哪、过期怎么办 | 获取、持久化、续期/重登 |
| 4 | 主代理编排逻辑 | LLM 工具循环是否正确点菜、补参、确认 | 工具循环、选 skill、补参、ask_user |
| 5 | 交付与业务闭环 | 四类交付与业务流程是否完整正确 | 流程完整性、交付边界、失败自愈 |
| 6 | 存储与工程基础 | 会话/资料隔离、编译/依赖/配置 | 多用户隔离、依赖、编译、配置 |

## 推进方式（自循环）

每个方向按「展开角度 → 扫描 → 定位 → 判定 → 处置」推进，结果分别写入：

- [`体检报告-确定项.md`](体检报告-确定项.md)：确定错误 → 直接修复并留痕；
- [`体检报告-待定项.md`](体检报告-待定项.md)：需你定夺 → 只记录、不擅自改。
