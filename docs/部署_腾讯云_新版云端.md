# 部署：新版云端（Device-as-Proxy）到腾讯云 140.143.144.28

> 手机 App（新版）连的是腾讯云 `http://140.143.144.28`。要跑通 Device-as-Proxy
> （skill_request 蓝图 → 手机直连 → skill_result），**腾讯云上的云端代码必须是新版**。
> 本文档列出需同步的文件与重启命令。

## 1. 需要上传/覆盖的新版文件（相对项目根）

```
cloud/cloud_orchestrator/channel/ws.py        # 第1条：skill_request/skill_result 协议
cloud/cloud_orchestrator/channel/bridge.py    # 第1条：bridge 增加 send_skill_request
cloud/cloud_orchestrator/adapters/registry.py # 第2条：run() 两段式 + 手机在线检查
cloud/cloud_orchestrator/adapters/glyy_api.py # 第3条：蓝图 + 手机执行通道 + login 走手机
cloud/cloud_orchestrator/adapters/tuniu_api.py# 第3条：蓝图 + 手机执行通道 + pay_url
cloud/cloud_orchestrator/core/agent.py        # 第2/5条：skill_run 带 device_id + 支付跳转
cloud/cloud_orchestrator/api/routes.py        # 第2条：skill run 路由 await
```

> 保留不动：`cloud/cloud_orchestrator/data/sessions/`（登录态目录，云端已不再写，
> 但保留历史文件无碍）、`cloud/config.json`（LLM/key 配置，服务器上那份为准）。

## 2. 部署命令（在腾讯云服务器上，或从本机同步）

```bash
# 方式A：scp 覆盖单个文件（本机 → 腾讯云，需能登录）
scp cloud/cloud_orchestrator/channel/ws.py root@140.143.144.28:/path/to/cloud_orchestrator/channel/ws.py
# ... 其余文件同理

# 方式B：整个 cloud_orchestrator 同步（排除 sessions）
rsync -av --exclude 'data/sessions' cloud/cloud_orchestrator/ root@140.143.144.28:/path/to/cloud_orchestrator/
```

## 3. 重启云端服务

```bash
# 找到旧进程并重启（在服务器上）
pkill -f "cloud_orchestrator.main"
cd /path/to/project && nohup env PYTHONPATH=. python3 -m cloud.cloud_orchestrator.main > /tmp/cloud.log 2>&1 &
sleep 5 && curl -s http://127.0.0.1:19000/health
```

## 4. 验证部署成功（关键）

部署后，在手机 App 里随便说一句会触发 skill 的话（如「查鼓楼医院皮肤科医生」），
腾讯云日志应出现 `skill_request` 下发（旧版代码不会有这个日志/消息类型）。

## 5. 注意事项

- 手机 App 已是新版（含 SkillExecutor），无需再装；
- 腾讯云 `cloud/config.json` 的 LLM key 已充值，可正常调用；
- 若腾讯云端口 19000 被防火墙挡，需放行（手机能连说明已放行）。
