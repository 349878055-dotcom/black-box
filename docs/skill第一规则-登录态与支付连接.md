# Skill 开发第一规则：登录态 + 支付连接（帽子理论 & 公开 H5 铁律）

> **做任何 skill，第一步必须先定死这几件事，顺序不能反：**
> **第 0 步（铁律）：挖「公开 H5 接口 + H5 请求头」，不是微信请求头。**
> **第一步：支付连接拿不拿得到（决定路径 A / B / C）。**
> **第二步：登录态走哪一路（四路之一）。**
> 这两件事都由"**帽子**"（环境身份/通道）决定，但**登录态和支付连接要分开判，不要混成一句话**。

---

## 〇、核心一句话

- **第 0 步（铁律）**：第一步要摸索的是「能拉起支付的登录态 + 浏览器环境」= **公开 H5 格式 + H5 请求头（不是微信请求头）**，从**微信缓存（wxapkg 解包/抓包）**里挖。
- **第一步判支付连接**：能拿 → 路径 A（全自动）；拿不到但有 H5 → 路径 B（确认页客户点）；**没公开 H5 / 返回不了连接** → 路径 C（只给链接，不做登录态）。
- **第二步判登录态**：分**四路**，其中**微信小程序授权路只用于初期探路，客户手机拿不到**，不能作为最终可交付的登录方式。

---

## 一、帽子理论（核心）

**每个 skill 就两个关键东西：**

```
① 登录态 —— 怎么登录
② 最后的支付连接 —— 怎么支付（拿不拿得到）
```

**"帽子"（环境身份）决定这两件事：**
- 帽子不同 → **登录方式不同**（H5 cookie / 微信授权 / Bearer token）
- 帽子不同 → **拿到的支付连接可能不同**，**有的帽子根本拿不到支付连接**

**关键死结**：帽子（UA 伪装）能拿到"权限"（如下单），但**支付要"真 SDK/真环境"**（如微信 JSAPI 要真微信 SDK），帽子替代不了。

---

## 二、第 0 步铁律：挖公开 H5，不要微信请求头

### 为什么必须"公开 H5"，而不是微信请求头

| 用什么环境/请求头 | 服务端判定 | 支付结果 | 虾米能否拉起 |
|---|---|---|---|
| **微信请求头 / 微信小程序通道** | 微信环境 | 锁 **JSAPI 支付**（wx.requestPayment） | ❌ 虾米不是真微信，拉不起 |
| **公开 H5 格式请求头** | 普通浏览器环境 | 返回 **H5 收银台 / https pay_url / alipays://** | ✅ 系统浏览器可拉起 |

**结论**：微信请求头会让支付被锁成 JSAPI；公开 H5 请求头才能拿到"能拉起的支付连接"。所以第一步要找的是**公开 H5**，不是微信请求头。

### 从哪里挖：微信缓存（wxapkg 解包 / 抓包）

平台通常只有微信小程序、没有独立 H5 页，但它背后**必然调了公开 HTTP 接口**。要从微信缓存里把这些挖出来：

```
① 抓包/解包微信小程序（wxapkg）→ 找到它调用的真实后端域名 + 接口
② 还原出「公开 H5 格式」的请求头（普通浏览器 UA / cookie / token / 签名），而不是 MicroMessenger 请求头
③ 确认这个 H5 接口能用公开方式访问（不依赖真微信环境）
```

这一步同时解决两件事：
- **找到能拉起支付的浏览器环境**（H5 收银台 / pay_url / alipays）；
- **找到 H5 格式的登录方式**（网页登录 或 H5 请求头登录）。

---

## 三、UA 双刃剑：微信 UA 反而可能让支付拉不起来

**支付连接的"格式"可能由"请求时带的 UA"决定**——哪怕全程纯 API，这一步也可能被 UA 反噬：

| 调接口拿支付连接时带的 UA | 服务端判定环境 | 返回的支付连接 | 虾米能否拉起 |
|---|---|---|---|
| **微信 UA（MicroMessenger）** | 微信环境 | 倾向返回 **JSAPI 参数**（wx.requestPayment 所需） | ❌ 虾米不是真微信，拉不起 |
| **普通浏览器 UA** | H5/浏览器环境 | 返回 **H5 收银台 / https pay_url** | ✅ 系统浏览器可拉起 |

**结论**：
- 想让"App 跳系统浏览器完成支付"的 skill（如 glyy 的 pay_url），**拿支付连接时优先用普通 UA**，否则支付被锁定成 JSAPI，反而拉不起来；
- 这是 **UA 双刃剑**：登录/下单环节可能**需要**微信 UA 过风控，但拿支付连接环节**不要**微信 UA、要普通浏览器 UA；
- ⚠️ 仅当**平台确实只有微信小程序格式、没有公开 H5（极少见）**时，才实测微信请求头能否拉到支付连接——极少数平台微信请求头反而是唯一通道，**要实测确认，不能靠猜**；
- **"纯 API"不是铁板**：即便全程纯 API，UA 在"拿支付连接"这一步仍可能决定支付是 JSAPI 还是 H5 收银台，必须在第一步就实测确认。

---

## 四、第一步：用 H5 请求头摸索下单，看能否返回支付连接

挖到公开 H5 后，**用它模拟下单，看能否返回一个支付连接**：

```
用公开 H5 请求头 → 调下单接口 → 看返回里有没有 pay_url / alipays:// / H5 收银台链接
```

**判定**：
- ✅ **能返回连接** → 继续做：登录态（H5 网页登录 / H5 请求头登录）+ 下单 + 拿支付连接 + 虾米拉起支付（路径 A）。
- ❌ **不能返回连接** → **skill 降级为"只搜索 + 给链接"**（路径 C，见下）：
  - 不做登录态（虾米不维护客户登录态）；
  - 只提供搜索/查询 + 返回一个**下单链接或查询链接**；
  - **客户自己打开链接 → 自己登录 → 自己操作**。

---

## 五、登录态四路（重点）

登录态按"帽子 + 拿法"拆成**四路**，每一路的关键词、请求头、客户可用性都不同，**必须分清楚，不要混**。

### 四路总表

| 路 | 帽子 | 登录方式 | 登录态载体 | 请求头关键 | 客户手机可用？ |
|---|---|---|---|---|---|
| **路 1** | H5 网页 | 内置浏览器打开登录页，真人输手机号+验证码（可能滑块） | **cookie** | `Cookie` + 浏览器 UA | ✅ 可用（真人配合一次） |
| **路 2** | H5/API 直连 | 云端/手机直连调登录接口（passport/mobilelogin） | **Bearer token** | `Authorization: Bearer` + appKey/sign/ts/nonce | ✅ 可用（可自动化）；⚠️ 拿支付连接时 UA 可能要切普通浏览器（见 UA 双刃剑） |
| **路 3** | **微信小程序授权** | 真人微信小程序内授权产生 code/encrypted_data/iv | **Bearer token** | 微信授权态 | ⚠️ **只初期探路，客户手机拿不到** |
| **路 4** | App | 真机 App 登录 + 抓通信拿 token/uuid | **App token** | token/uuid + 设备指纹 | ✅ 可用（需真机 App） |

### ⚠️ 路 3（微信小程序授权）铁律

**微信小程序授权只用于初期探路**（工程师在真微信里授权一次，拿 token 验证接口链路、破解请求体），**不能作为最终交付给客户的登录方式**：

- 客户手机上跑 skill 的是虾米 App（内置浏览器/HTTP 通道），**不是真微信环境**，无法完成 `wx.login` 小程序授权；
- 依赖"真人微信小程序授权"的 skill，**探路能通，客户端不可用**——这类 skill 要么换路（如路 2 API 直连、或路 1 H5），要么标注为"仅内部验证用"。

### 路 1 与路 2 的本质区别（易混点）

| | 路 1：H5 网页登录 | 路 2：API 直连登录 |
|---|---|---|
| 原理 | 内置浏览器打开页面，真人操作 | 直接调登录接口拿 token |
| 载体 | cookie | Bearer token |
| UA 地位 | **决定性**（骗页面风控） | **只是请求头字段**（可任意填） |
| 真正命门 | 真实 WebView + 真人 + 浏览器指纹 | 签名算法 + token + 风控参数 |
| 例 | 途牛（腾讯滑块只能真人） | glyy（短信验证码 API 登录） |

**结论：路 1 和路 2 虽然都叫"H5"，本质是两种帽子（cookie vs token），请求头完全不同，第一步必须定死走哪一路。**

---

## 六、三种路径定级（skill 定性）

| 路径 | 条件 | 做法 | 客户动作 |
|---|---|---|---|
| **路径 A** | 登录态能拿 + 支付连接能返回 | 登录态 + API 下单 + 拿支付连接 + 虾米拉起支付 | 最后点确认 |
| **路径 B** | 登录态能拿 + 支付连接**拿不到**（如 JSAPI） | 做到"下单前"，生成确认页/订单链接，客户自己确认+支付 | 打开链接 + 点确认 |
| **路径 C** | **确实没有公开 H5 格式**（极少，只有微信小程序格式） | 见下"路径 C 两种分支" | 见下 |

**路径 C 新增说明（两种情况，别一刀切）**：
1. **下单返回不了连接**（有 H5 但出不来支付链接）→ **只搜索 + 给下单/查询链接，不做登录态**，客户自己打开登录操作；
2. **确实没有公开 H5 格式、只有微信小程序格式（极少）** → 别急着判死：**先用微信请求头试一下能不能拉到支付连接**，微信请求头有时反而能返回可拉起的支付连接；试不通才退回"只给链接、客户自己登录"。
   - ⚠️ 区分：一般带微信 UA 会被锁 JSAPI 拉不起（UA 双刃剑）；但**极少数只有微信小程序格式的平台**，微信请求头反而是唯一能拿到支付连接的通道——要实测确认，不能靠猜。

## 七、帽子类型 + 四个 skill 验证表

### 帽子类型（环境身份）

| 帽子 | 登录态 | 典型权限 | 支付连接 |
|---|---|---|---|
| **H5 帽子** | H5 cookie | 看店/菜单/加购/结算（查询级） | 看平台：支付宝 scheme 可拉；微信 JSAPI 拿不到 |
| **微信帽子** | 微信授权/小程序态 | 下单（交易级，支付除外） | weapp 通道能拿，但支付要真微信 SDK |
| **App 帽子** | App token/uuid | 直接调 App API | 需 mtgsig 签名 |
| **接口 token** | Bearer token | 纯接口 | 接口内处理 |

### H5 帽子下的两种登录方式

**H5 方式进去，登录有 2 种：**

| 登录方式 | 原理 | 实测 | 取舍 |
|---|---|---|---|
| **① API 登录** | 云端直连调登录接口（如 `passport.meituan.com/mobileloginapply`→`mobilelogin`） | ✅ 美团云端可直连 HTTP 200 | 快、可自动化；但可能过滑块/图形验证、要设备指纹 → 可能被拦 |
| **② H5 网页登录** | 虾米浏览器打开登录页，真人输手机号+验证码 | ✅ 已通 | 稳、能过滑块；但要真人配合一次 |

**通常组合**：**API 登录拿 token（自动）→ 失败/被拦时降级 H5 网页登录（真人配合）**，登录态存凭据库复用。

### 四个 skill 定性表（修订版）

| Skill | 第一步（挖到的环境） | 登录态 | 支付连接 | 路径 |
|---|---|---|---|---|
| **glyy** | 公开 H5 API（ih.njglyy.com/caring/api，普通 UA 可访问） | ✅ 路 2（H5 请求头登录，Bearer+refresh 续期） | ✅ pay_url（https，App 跳系统浏览器） | **A 全自动** |

## 八、新 skill 开工第一步清单（铁律版）

```
□ 第 0 步（铁律）：挖公开 H5，不要微信请求头
   → 抓包/解包微信小程序（wxapkg），找到背后的公开 H5 接口域名 + 接口
   → 还原「公开 H5 格式」请求头（普通浏览器 UA / cookie / token / 签名）
   → 确认该 H5 接口不依赖真微信环境，能公开访问
   → ⚠️ 若怎么都挖不到公开 H5（只有微信小程序格式，极少见）→ 记为路径 C 分支 2，先实测微信请求头能否拉到支付连接，别直接放弃
□ 第一步（先判）：用 H5 请求头摸索下单，看能否返回支付连接
   → 能返回（pay_url / alipays / H5 收银台）→ 路径 A 或 B
   → 不能返回 → 路径 C 分支 1：只搜索 + 给链接，不做登录态，客户自己登录
   → ⚠️ UA 双刃剑实测：拿支付连接优先用"普通 UA"（避免被锁 JSAPI）；仅当平台确实只有微信小程序格式时，才试微信请求头能否拉到支付连接
□ 第二步（再判）：登录态走哪一路（能做才做）
   → ① H5 网页登录（cookie）？② H5 请求头登录（token）？
   → ⚠️ 微信小程序授权只探路，客户手机拿不到，不作为可交付方式
   → 登录态能拿吗？存哪？能复用/续期吗？
□ 第三步：写进 skill 文档（挖到的公开 H5 + 请求头 + 登录路 + 支付连接格式 + 路径 A/B/C + 客户可用性 + UA 切换策略）
```

---

## 九、一句话

**第 0 步（铁律）= 在微信缓存里挖出「公开 H5 接口 + H5 请求头」（不是微信请求头），用它摸索下单：能返回支付连接 → 做登录态 + 下单 + 支付（A）；返回不了 → 只搜索 + 给链接、不做登录态、客户自己登录（C）；只有微信小程序格式的极少平台 → 先用微信请求头实测能否拉起支付。** 这是每个 skill 的定性标准，先定死再往下做。
